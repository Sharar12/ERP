# Project Prompt: Build a Universal, Modular, Multi-Tenant ERP System

Act as a senior software architect, UI/UX designer, database architect, and full-stack development team. Design and develop a complete, production-ready **Universal ERP (Enterprise Resource Planning) Web Application** that can be reused, customized, and deployed for businesses across different industries and countries.

The system must be modular, scalable, secure, configurable, and suitable for small businesses, medium-sized companies, and large enterprises. It should not be limited to any single industry.

Do not build just a dashboard or static UI prototype. Build a functional ERP platform with real backend logic, database integration, authentication, authorization, business workflows, reporting, and CRUD operations.

## Development Architecture
Use a clean, maintainable, modular architecture.

- `/backend` — Laravel application
- `/docs` — Technical documentation

The frontend must communicate with Laravel through versioned APIs such as `/api/v1/`.

Never place business-critical logic exclusively in the frontend.

# 2. Core Vision: Universal ERP

Create one reusable ERP platform that can serve different business types without requiring a completely different application for each industry.

The system should support businesses such as:

- Manufacturing
- Retail and wholesale
- E-commerce
- Distribution
- Trading
- Construction
- Healthcare administration
- Education administration
- Restaurants and hospitality
- Logistics and transportation
- Professional services
- Real estate
- Import and export
- General corporate businesses

Use a **modular architecture** where each business can enable only the modules it needs.

For example:
- A retail company can enable Sales, POS, Inventory, Purchasing, and Accounting.
- A manufacturing company can enable Production, Inventory, Procurement, Quality Control, and Accounting.
- A service company can enable CRM, Projects, HR, Invoicing, and Accounting.

Avoid hardcoding industry-specific assumptions into the core system.

# 12. Database Architecture

Design a normalized, scalable MySQL database.

Use consistent naming conventions, foreign keys, indexes, unique constraints, and appropriate data types.

The architecture should include common system tables such as:

- tenants
- tenant_users
- branches
- departments
- warehouses
- users
- roles
- permissions
- role_permissions
- user_roles
- modules
- tenant_modules
- subscriptions
- settings
- custom_fields
- custom_field_values
- workflows
- workflow_steps
- approval_requests
- notifications
- attachments
- audit_logs

Create separate domain tables for the individual ERP modules.

Important database principles:

- Every tenant-owned record must be scoped to its tenant.
- Use consistent tenant and ownership relationships.
- Add indexes for frequently filtered fields.
- Use database transactions for critical operations.
- Prevent duplicate document numbers within their configured scope.
- Use decimal types for financial values rather than floating-point types.
- Store timestamps consistently and display them in the tenant's timezone.
- Use soft deletes only where business requirements allow them.
- Do not use one oversized universal table for unrelated business entities.
- Avoid unnecessary duplication of data.
- Use appropriate cascading and restrictive delete behavior.
- Maintain historical records for important business transactions.

Create complete Laravel migrations, factories, and seeders.

Provide an Entity Relationship Diagram (ERD) and database documentation.

# 15. Business Rules and Data Integrity

All modules must work together through consistent business workflows.

Examples:

**Sales workflow:**

Quotation → Sales Order → Delivery → Invoice → Payment → Accounting Entries

**Purchase workflow:**

Purchase Request → Approval → Purchase Order → Goods Receipt → Supplier Bill → Payment → Accounting Entries

**Inventory workflow:**

Goods Receipt → Stock Increase → Stock Movement Record → Inventory Valuation

**Manufacturing workflow:**

Production Order → Raw Material Consumption → Production → Finished Goods → Inventory Update

**HR workflow:**

Leave Request → Approval → Leave Balance Update

Ensure that related records update correctly and that failed transactions do not leave partially completed business operations.

Define which documents are drafts, submitted, approved, posted, cancelled, or reversed.

Maintain a complete history of important status changes.

# 23. Strict Development Instructions

Follow these requirements throughout the project:

1. Build a real, functional application, not just a visual mockup.
2. Use the specified technology stack without replacing it with another framework.
3. Keep Next.js and Laravel as separate applications.
4. Use Laravel as the authoritative backend for business logic and permissions.
5. Use MySQL as the primary relational database.
6. Implement secure tenant isolation from the beginning.
7. Build reusable components, services, modules, and workflows.
8. Avoid hardcoded tenant IDs, business data, roles, currencies, and tax rules.
9. Use configuration-driven behavior wherever appropriate.
10. Do not create fake API integrations or pretend that unfinished functionality is working.
11. Connect every implemented frontend feature to its real backend functionality.
12. Do not use placeholder buttons for actions that are advertised as functional.
13. Provide useful loading, validation, success, and error states.
14. Use consistent coding standards and meaningful naming conventions.
15. Keep business rules centralized in the backend.
16. Protect sensitive operations with permissions and audit logs.
17. Maintain data integrity across connected modules.
18. Include automated tests for critical workflows.
19. Update documentation as the architecture evolves.
20. Do not silently skip requirements. Document any feature that cannot be completed in the current development phase.

# 24. Final Expected Product

The final product must be a professional, reusable, modular, multi-tenant ERP SaaS platform.

A new business should be able to:

1. Register or be onboarded by a platform administrator.
2. Create its company profile.
3. Configure its branches and departments.
4. Select its business type.
5. Activate the modules it requires.
6. Configure its users, roles, and permissions.
7. Customize its company settings and branding.
8. Start managing its business through the ERP.
9. Generate reports and monitor business performance.
10. Expand its ERP functionality as its business grows.

The most important architectural objective is:

**Build one universal ERP foundation that can be adapted to different businesses through modular features, configuration, permissions, custom fields, and reusable workflows — without needing to rebuild the application for each new business.**

Start by designing the architecture, database schema, module boundaries, and development roadmap. Then implement the system phase by phase, ensuring every completed feature is functional, tested, secure, and properly integrated.
